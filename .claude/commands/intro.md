너는 오케스트레이터다. 아래 두 단계를 **이 순서대로** Agent 도구로 실행한다. 두 번째 단계는 첫 번째 결과 파일에 의존하므로 병렬로 돌리지 않는다.

주제: `$ARGUMENTS` (비어 있으면 "이번 주 전체").

## 단계 1 — intro-writer (브리핑 작성)
- Agent 도구, `subagent_type: "intro-writer"`.
- 브리프: "주제: <`$ARGUMENTS` 또는 '이번 주 전체'>. 최근 7일 수집 항목에서 카테고리가 겹치지 않는 3개를 골라 원문을 확인한 뒤, 지정 템플릿으로 reports/intro-YYYY-MM-DD.md 를 작성하라(KST 날짜). 커밋하지 마라. 파일 경로와 선정 결과를 보고하라."
- 중단 조건: 파일이 만들어지지 않았거나 보고 상태가 "중단"이면 **중단**한다. 사유를 보고하고 단계 2를 실행하지 않는다. (예: 카테고리 3개 미만, 주제 후보 부족)
- 성공하면 생성된 파일 경로(예: `reports/intro-2026-11-07.md`)를 기록해 단계 2에 넘긴다.

## 단계 2 — deploy-guardian (커밋·푸시)
- Agent 도구, `subagent_type: "deploy-guardian"`.
- 브리프: "아래 파일 하나만 테스트 게이트 후 커밋하고 푸시하라. 커밋 종류: feat. 요약: 수업 도입 브리핑 <주제 또는 이번 주 전체> (YYYY-MM-DD). 파일: <단계 1의 경로>. 금지 파일 검사와 비밀값 검사를 수행하라. reports/ 의 다른 파일은 스테이징하지 마라."
- 중단 조건: 상태가 "중단"이면 그 사유를 그대로 보고한다. "커밋할 변경 없음"이면 같은 내용의 파일이 이미 커밋되어 있다는 뜻이므로 그대로 보고한다.

## 최종 보고
```
## /intro 결과
- 주제: <값 또는 이번 주 전체>
- 단계 1 intro-writer: <파일 경로, 선정 3건 카테고리 한 줄>
- 단계 2 deploy-guardian: <상태 한 줄 / 실행 안 함>
- 중단 지점: <없음 / 단계 N: 사유>
- 확인 필요 표시: <개수 — intro-writer 보고에서 옮긴다>
```

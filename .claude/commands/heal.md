description: 수집기 진단·치유 → 운영 상태 점검 → 테스트 통과 시 커밋·푸시 (trend-healer → ops-monitor → deploy-guardian)
argument-hint: "[추가 지시, 선택]"
---

너는 오케스트레이터다. 아래 세 단계를 **이 순서대로** Agent 도구로 실행한다. 각 단계는 앞 단계의 결과에 의존하므로 병렬로 돌리지 않는다.

추가 지시가 있으면 `$ARGUMENTS` 로 받는다. 없으면 기본 동작만 한다.

## 단계 1 — trend-healer (진단·치유)
- Agent 도구, `subagent_type: "trend-healer"`.
- 브리프: "최근 수집 로그와 runs.failed_sources 에서 오류를 찾아 원인 가설을 세우고, 필요하면 backend/ 를 최소 수정하라. 수정 전 재현 테스트를 추가하고, 전체 pytest 통과와 스모크 실행을 확인하라. 커밋하지 마라. 지정 형식으로 보고하라." 여기에 `$ARGUMENTS` 를 덧붙인다.
- 중단 조건: 보고 상태가 "해결 실패"이거나 pytest 가 실패한 상태로 끝났으면 **중단**한다. 이후 단계를 실행하지 않는다.
- 변경 파일 목록을 기록해 둔다 (단계 3에 넘긴다).

## 단계 2 — ops-monitor (상태 점검)
- Agent 도구, `subagent_type: "ops-monitor"`.
- 브리프: "수집 생존(runs.jsonl 마지막 실행 시각), data/daily/*.jsonl 누적 건수 증가, 소스별 24시간 성공률을 점검하고 지정 형식으로 보고하라. 코드는 건드리지 마라."
- 중단 조건: 종합 판정이 **이상**이면 **중단**한다. 이 경우 단계 1에서 고친 코드는 커밋하지 않고 로컬에 남겨 둔다. 사유와 함께 사용자에게 보고한다.
- 주의(판정 "주의")면 중단하지 않고 보고에 포함한다.

## 단계 3 — deploy-guardian (커밋·푸시)
- 단계 1에서 **변경 파일이 하나도 없으면** 이 단계는 건너뛰고 "배포할 변경 없음"으로 보고한다.
- Agent 도구, `subagent_type: "deploy-guardian"`.
- 브리프: "아래 파일만 테스트 게이트 후 커밋하고 푸시하라. 커밋 종류: fix. 요약: <단계 1의 수정 요약>. 파일: <단계 1의 변경 파일 목록>. 금지 파일 검사와 비밀값 검사를 반드시 수행하라."
- 중단 조건: 상태가 "중단"이면 그 사유를 그대로 보고한다.

## 최종 보고
세 단계 결과를 한 번에 정리한다. 단계가 중단됐으면 어느 단계에서 왜 멈췄는지를 맨 위에 쓴다.

```
## /heal 결과
- 단계 1 trend-healer: <상태 한 줄>
- 단계 2 ops-monitor: <종합 판정 한 줄>
- 단계 3 deploy-guardian: <상태 한 줄 / 건너뜀 / 실행 안 함>
- 중단 지점: <없음 / 단계 N: 사유>
- 다음 조치: <사용자가 해야 할 일, 없으면 "없음">
```
